# Reliability Envelope Reproducibility Repository

This repository supports the manuscript:

Decision-Oriented Reliability Envelopes for Complex Systems under Multi-Source and Profile-Dependent Uncertainty

It contains code, configuration files, controlled synthetic inputs, processed numerical tables, and figure source data for reproducing the reported Case A/B/C analyses. The revision evidence is archived at tag `p0-2026-10-14`. Manuscript and reviewer-response files are maintained separately.

## Contents

- `simulation.py`: top-level entry point.
- `scripts/`: controlled Case A/B simulation, C-MAPSS Case C analysis, manuscript-number generation, and diagnostic checks.
- `config/`: numerical experiment configuration.
- `data/`: synthetic controlled-case parameter and evidence tables.
- `results/`: processed numerical tables used by the manuscript.
- `figure_source_data/`: copy of the CSV result tables used as source data for manuscript figures.
- `complete_revision_analysis.py`: data-only reproduction of the verified revision analyses.
- `verify_revision_results.py`: comparison of a fresh run with the archived revision evidence.
- `revision_results/`: revised tables, independent numerical audits, declared nonlinear inputs, and provenance.

## Python environment

Create a Python environment and install:

```bash
pip install -r requirements.txt
```

The package was prepared with Python 3 and the versions listed in `requirements.txt`.

For the revised numerical tables, use Python 3.13.2 and `requirements-revision.txt`. The older requirements and `results/` document the original computational environment and outputs. The point-weight solver now explicitly uses SLSQP tolerance `1e-12` and a 1000-iteration limit, matching the method specification. This correction can change the original table values slightly. The manuscript figure assets are not regenerated by the revision entry point.

## C-MAPSS data

The raw NASA C-MAPSS text files are not redistributed in this repository. Obtain the public dataset from the NASA Ames Prognostics Data Repository:

https://data.nasa.gov/dataset/Turbofan-engine-degradation-simulation-data-set/vrks-gjie

Place the following files in a local directory:

- `train_FD001.txt`, `test_FD001.txt`, `RUL_FD001.txt`
- `train_FD002.txt`, `test_FD002.txt`, `RUL_FD002.txt`
- `train_FD003.txt`, `test_FD003.txt`, `RUL_FD003.txt`
- `train_FD004.txt`, `test_FD004.txt`, `RUL_FD004.txt`

By default, the scripts look for these files at `../public_data/CMAPSS` relative to the repository root. To use another location, set the environment variable `CMAPSS_DIR`.

PowerShell example:

```powershell
$env:CMAPSS_DIR = "D:\data\CMAPSS"
python simulation.py
```

## Reproduction steps

From the repository root:

```bash
python simulation.py
```

This regenerates the controlled Case A/B outputs, the C-MAPSS Case C summaries, the manuscript-number macros, and the manuscript figures.

## Expected checks

- Case A/B CSV files are regenerated under `results/`.
- C-MAPSS FD002 and FD004 each have six operating-condition clusters in `results/cmapss_dataset_summary.csv`.
- `results/cmapss_crossfit_leakage_audit.csv` reports zero train-evaluation overlap.
- Reliability envelope columns contain finite values and satisfy lower <= upper.
- `results/cmapss_epsilon_monotonicity_summary.csv` reports nondecreasing width as the admissible set expands.

The finite scenario-wise envelopes are exact only over the declared finite scenarios encoded in the scripts and configuration. They are not global robust bounds and do not represent deployed industrial certification.

## Verified revision reproduction

Install the revision dependencies, supply the twelve C-MAPSS text files above, and run:

```bash
pip install -r requirements-revision.txt
python complete_revision_analysis.py --cmapss-dir /path/to/CMAPSS --output-dir /path/to/fresh-results
python verify_revision_results.py --reproduced /path/to/fresh-results
```

The script recomputes the four training-fitted predictive sources, 30 profile/fold evaluations, six full-data weight refits, and 500 stratified calibration bootstraps per fit. It independently reconstructs engine folds and probabilities, evaluates Brier scores and fold gaps, and checks small quadratic optimization problems by enumerating simplex faces. Every engine appears in one evaluation fold; public test labels are used only in the calibration folds for weight learning. Full-data weight refits use all these labels and supply no additional held-out evaluation.

Training sensitivity uses 200 training-engine resamples, seed `20261013`, and one random stream across FD001--FD004. Feature extraction, the operating-condition partition, folds, and predictive weights remain fixed. Log-life regression normalization and residual standard deviations are refitted. The output quantiles describe the companion point pool conditional on this protocol; they are not confidence intervals for the original envelope.

The nonlinear extension is an explicit reconstruction of the revision specification. It uses the three existing Case B Gamma priors and four existing Case A full-source strength vectors, fixed Weibull shapes, twelve tests per component, and 20,000 samples per prior, seed `20261014`. `nonlinear_inputs.json` records every scenario and evidence profile. This declared four-vector specification replaces a previously undocumented calculation; its outputs should not be treated as recovery of missing original files.

`hypothetical_budget_curves.csv` reproduces assumed exponential contractions without simulating observations or updating a posterior. These curves provide no empirical evidence that one validation policy outperforms another. Threshold sensitivity changes only the externally stated requirement.

`run_provenance.json` records dependency versions, raw-file hashes, numerical-source hashes, and seeds. The comparison uses absolute tolerance `1e-10` and excludes timing columns only. The curvature-radius diagnostic additionally uses relative tolerance `1e-9`, because small eigenvalues amplify floating-point parsing differences; probability outputs retain the absolute-only tolerance. Reproduction does not download external data or alter figure files. The forecasts evaluate total-life survival at observed age plus mission length, without conditioning by survival at the observed age; they are evaluated as candidate probabilities against the strict event `RUL > mission_cycles`.
